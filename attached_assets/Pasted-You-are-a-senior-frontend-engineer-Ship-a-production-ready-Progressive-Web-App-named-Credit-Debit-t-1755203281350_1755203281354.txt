You are a senior frontend engineer. Ship a production‑ready Progressive Web App named Credit Debit that mirrors the provided screenshots (drawer + sort menu; Cash Book tabs Daily/Weekly/Monthly/Yearly; customer detail with balance toggle; invoice builder; add item/customer forms; Settings with date/time/currency/language/dark mode/fingerprint‑like lock).

Stack & Architecture

React + TypeScript (Vite or Next.js App Router; choose one and stick to it).

UI: Material UI (MUI v5) with Material‑3 look; mobile‑first responsive layout; CSS variables for theming.

State: Zustand (or Redux Toolkit—pick one).

Data (offline‑first): IndexedDB via Dexie with migrations & typed models.

Queries/caching: TanStack Query for async ops.

PWA: Service worker with Workbox (precaching, runtime caching, background sync).

Auth/backup (optional, no server required): Google Drive using OAuth (Google Identity Services) + Drive REST; store DB export files in user’s Drive.

Files: File System Access API for local export/import; Web Share API to share PDFs; Web Share Target to receive images (receipts).

PDF/Excel: pdfmake or jsPDF + autoTable; xlsx (SheetJS).

Notifications/Reminders: Web Notifications + service worker; optional Web Push subscription for scheduled reminders (use Background Sync/Periodic Sync when available; graceful fallback to calendar/ICS download).

App lock: Passcode stored in IndexedDB + WebAuthn for biometric unlock where supported.

i18n: react-i18next.

Business Rules

Running balance

credit = customer owes you (Due ↑).

debit = customer paid you (Due ↓, Advance ↑).

Transfers: create two linked entries (from → to); prevent same‑account transfers.

Validation: positive amounts, required fields; undo toast on delete.

Searching & sorting by name/amount/category/last transaction.
